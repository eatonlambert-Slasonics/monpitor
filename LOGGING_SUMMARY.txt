================================================================================
USAGE
================================================================================

Basic Usage:
  python server.py                    # INFO level (default)
  python server.py -v                 # DEBUG level
  python server.py -v -v              # Extra debug output
  python server.py --log-file PATH    # Custom log file

Check Server Status:
  curl http://localhost:8080/health   # Health status
  curl http://localhost:8080/stats    # Statistics JSON

View Logs:
  tail -f monpitor.log               # Follow logs
  grep ERROR monpitor.log            # Search errors
  grep "PC-a1b2c3d4" monpitor.log   # Specific connection

Browser Debugging:
  Open DevTools (F12) → Console tab
  Access logs via: ClientLogger.getLogs()

================================================================================
LOGGING LEVEL RECOMMENDATIONS
================================================================================

Production:   INFO level
              • Standard logging for production environments
              • Captures important events and errors
              • Minimal performance overhead

Testing:      DEBUG level (-v)
              • Detailed diagnostic information
              • Useful for functionality verification
              • Minor performance impact

Troubleshooting: DEBUG level with file monitoring
              • Follow logs in real-time: tail -f monpitor.log
              • Check health endpoint: curl .../health
              • Review statistics: curl .../stats
              • Analyze patterns and timing

Deep Debugging: Extra verbose (-v -v) with custom log file
              • Maximum diagnostic detail
              • Full stack traces and context
              • Performance impact acceptable for debugging only

STATISTICS ENDPOINT
================================================================================

Endpoint: GET /stats

Returns JSON with:
  • Timestamp (ISO 8601 format)
  • Connection statistics (total, active, failed)
  • Track statistics (received, ended)
  • Error counter
  • Current active connection count

Useful for:
  • Monitoring server health
  • Detecting connection issues
  • Tracking usage patterns
  • Integration with monitoring systems
  • Real-time metrics dashboard

Example:
  curl http://localhost:8080/stats | jq '.stats.connections_active'

================================================================================
HEALTH CHECK ENDPOINT
================================================================================

Endpoint: GET /health

Returns:
  {

  }
